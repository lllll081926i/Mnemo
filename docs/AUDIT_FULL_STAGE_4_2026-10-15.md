# 全量审计整改：阶段四

## 分享转存回执 B-15

- 分享转存先验证账号、空间、来源、所选文件唯一性与会话必要字段。检查点保存失败时不提交远端请求。
- 本机账本 `share_imports.json` 保存源文件、目标文件、全部可辨识任务 ID、状态和时间。不保存提取码、访问令牌、分享会话或原始服务端错误。
- 按账号串行处理转存与账号移除。批次标识包含账号、空间、分享、规范化目标目录和排序后的选择集；重复批次直接返回已有回执，重叠选择要求先核对原批次。重启不清除未知结果，也不重新创建文件。
- 远端明确受理记为 `submitted`，缺失或丢失回执记为 `unknown`，不把 HTTP 成功或返回源文件列表当成最终完成。
- PikPak 保存批次全部任务 ID。手动核对调用已有单任务 GET 接口，要求返回 ID 与请求匹配；全部任务完成后才标记完成。某个任务失败可能伴有部分文件已转存，仍禁止盲目重发。
- 阿里保存同步目标 ID 和异步任务 ID。同步回执的空间必须匹配目标空间；异步回执保持已受理。123 保存可辨识任务 ID，保持已受理。
- 未确认阿里开放平台与 123 的异步查询协议时，不套用其他协议的路径，不根据同名文件猜测完成。页面明确要求核对目标目录。这些真实服务端协议仍需测试账号验收。
- 远端请求已发送但最终账本保存失败时，向前端返回完整内存回执及保存失败标志；原始 pending 检查点阻止再次提交。页面允许复制回执，不通过抛错丢弃服务端标识。

## 页面与兼容

- 独立 `ShareImportHistory` 组件展示本机转存状态、核对状态、复制回执和打开原目标目录。查询失败保留旧记录，移除账号后不显示该账号回执。
- 保留旧 `SaveImportedShare` 绑定，内部转入同一账本，不提供绕过防重的旧写入口。旧接口返回的是已受理源 ID，不是目标 ID 或最终完成保证。
- 账号删除等待在途转存退出后清理账本。某项本机清理失败仍执行其他清理并更新账号界面，最后返回聚合错误。
- 修正浏览器验收脚本的过期搜索选择器，使用现有可访问名称；补充新绑定的测试替身。
