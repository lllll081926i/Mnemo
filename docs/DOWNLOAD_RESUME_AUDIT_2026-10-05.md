# 下载断点续传审查（2026-10-05）

## 结论

光鸭存在此前未补齐的路径：修改时间不一致时安全降为完整单流，但单流不保存检查点，重启后只能重下。小文件也走同一无断点路径。分段下载虽然已支持部分分片恢复，检查点仍主要在分片完成和正常停止时保存；开发进程异常结束时，正在下载的分片可能没有持久化前缀。

本轮补齐这些公共下载路径，没有重复修改已完成的迅雷分片续传修复。任务重启时从有效本地检查点恢复显示，避免任务列表的五秒保存周期导致已有断点显示为零。

## 修复内容

- 单流使用 `stream`、`stream_bytes` 保存实际连续字节及实际响应的资源身份。恢复不依赖探测请求与完整响应的修改时间完全相同。
- 条件 Range 恢复核对资源身份、起始偏移、响应长度和总大小。服务端限制单次范围长度时，有界续接下一段，不重复已确认字节。
- 条件 Range 返回完整响应时从头覆盖，不能追加完整文件。身份不一致的分段正文不写入旧文件；废弃失效身份检查点，后续重试可以重新下载。
- 分段和单流每秒先同步文件再原子保存检查点。正常暂停、错误和退出再保存最终字节；保存失败会停止工作并报告实际错误。
- 分片检查点保存正在写入的有效前缀；完整前缀规范化为已完成片，避免恰好在分片收尾前保存无效状态。
- 重启恢复检查临时文件和资源 ID，以检查点字节数更新任务进度，并清除旧速度和阶段；不能用稀疏文件长度伪造进度。
- 弱 ETag 不能单独授权字节续传；需要同时匹配修改时间。强 ETag 相同时仍优先确认资源身份。
- 已存在的分片检查点继续兼容；旧版无检查点的单流临时文件无法可靠推算有效字节，不冒险复用。

## 边界

- 服务端忽略 Range、无法确认字节身份或资源实际变化时，完整重下或明确报错，不能混合旧字节。
- 签名 URL 更换后，需要相同资源 ID 以及实际响应身份确认；不能只凭文件名和大小复用。
- 正常退出等待下载线程保存断点。强制结束进程最多恢复至最近一次成功检查点，不能保证保留最后尚未同步的字节。
- 原版单流已丢失的检查点无法追溯补回。直链任务仍不将 URL 和鉴权头落盘，重启后需要重新提供地址；不削弱既有凭据保护。
- 真实光鸭 CDN 和其他网盘账号尚未实测；公开接口之外的权限、风控及 CDN 行为仍需实际下载验收。

## 核验

新增本地 HTTP 回归覆盖小文件、新签名 URL、请求头和请求鉴权、受限范围续接、光鸭实际响应修改时间、条件 Range 被忽略、身份/范围/长度异常、临时文件截断、异常结束前的分段与单流检查点。增加全部 14 种网盘任务标识的分段/单流恢复测试，共 28 个恢复场景。
