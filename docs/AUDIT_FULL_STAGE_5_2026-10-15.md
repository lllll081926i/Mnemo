# 全审计整改：阶段五

## 范围

处理 M31、M32 的依赖来源和许可归档，以及 M27 的发布来源证明。同步实际工具链和发布质量门槛，不发布新版本，不生成本地 Mnemo 可执行文件或安装包。

## 实施

- 新增无外部 Node 依赖的来源检查与归档工具。固定 SheetJS 外部 tarball 的版本、来源、SHA-512 和声明许可证；校验全部锁定包和根清单一致性；拒绝路径替换、未知来源、弱摘要及 URL 凭据。
- 在 npm、Wails 和 CI 安装入口禁用依赖脚本，防止字体依赖 postinstall 获取不固定的网络输入。来源检查在 CI 安装前执行。
- 归档原始许可证、署名与含许可正文的 README。生成输入摘要和提交标识；缺失原文明确告警，不补造许可。Go 与前端分别生成 CycloneDX SBOM。
- Linux 包许可证从错误的 MIT 修正为 GPL-3.0-only；Windows、Linux 各格式和 macOS 包接入同一归档，Release 单独提供合规归档。发布附件门槛同步增加归档。
- 标签发布任务生成 Artifact Attestation；仅此任务授予证明写权限。证明失败时不公开 Release。AppImage 工具增加执行前固定 SHA-256 验证。
- 更新弹窗明确应用内校验不等同发布者签名；文档提供独立核验指令和信任边界。
- 用户自行更新本机 Go 至 1.27.2。随后使用该版本核验，并固定云端版本与 `GOTOOLCHAIN=local`。依赖补丁包含 x/net、x/crypto、x/sys、x/sync 和 x/text 更新。

## 验证

- 来源工具 5 项测试通过；实际 275 项来源检查通过。
- Node 24.22.0 临时干净目录安装禁用脚本后，前端 27 个文件、257 项测试通过；生产构建通过。
- 缓存离线安装与生产重建通过；保留既有大分块警告。初次临时目录漏复制共享验证脚本，补齐目录结构后测试通过，未修改应用测试以规避错误。
- 完整 npm audit 通过，0 条已知漏洞。首次远端审计遇到 TLS 中断，使用系统代理重试通过。
- Go 1.27.2 的 `go test ./...`、`go test -race ./...`、`go vet ./...`、`go build ./...` 通过。`govulncheck@v1.9.0` 返回 No vulnerabilities found。
- actionlint 通过；独立 YAML 解析和 25 段 Bash 语法检查通过。格式检查和差异空白检查通过。
- 本机归档实际包含 224 个组件；Go SBOM 包含 43 个组件，前端 SBOM 包含 72 个组件。二者扫描范围不同，不把数目差异伪装为每个平台的链接清单。

## 未完成验收

- 本机实际安装的 4 个组件缺少可识别许可正文，详见 `docs/SUPPLY_CHAIN.md`。其他平台可选组件以实际构建清单为准，许可义务仍需人工核对。
- 新的五平台云端打包、证明生成及最终附件验证尚未运行；本阶段不创建标签或发布 Release。
- 原生签名证书、真实跨系统安装、彻底离线依赖镜像、逐字节可重复二进制均不属于已完成项。
