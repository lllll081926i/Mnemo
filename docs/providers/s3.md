### 跨盘迁移与哈希边界

S3 当前不声明 `ProvideHashes` 或 `RapidUploadHashes`，也不把 `ETag` 当作 MD5。单段 PUT 的 ETag 在部分实现中可能与 MD5 相同，但 multipart、服务端加密和兼容 S3 服务均不能保证这一语义；标准 S3 也没有“按内容哈希查重并创建目标对象”的通用 API。`CopyObject` 需要已知且有权限访问的源对象键，不属于跨 provider 的哈希秒传。

迁移到 S3 当前走经过长度校验的临时文件上传。没有直接把 `io.Pipe` 接到 `PutObject`：通用 endpoint 的 SigV4 实现可能要求可重放/可寻址请求体，而可靠的未知长度 multipart 流还需要完整定义分片上限、重试重放、取消清理与恢复状态。在这些语义完成并覆盖兼容服务测试前，保留 spool 比宣称不可靠的流式能力更安全。

## 7. 临时分享（share.go）

✅ 通过 S3 `GetObject` 预签名 URL 创建单文件临时访问链接，只提供 1 天、7 天选项；不支持提取码，也不保存到本地分享历史。该链接不是服务商托管的永久分享，凭据有效期或权限不足时可能提前失效。

## 本轮审计结论

1. ✅ **forcePathStyle 可配置**，并支持 `sessionToken` 与 `BasePath`。
2. ✅ **目录递归操作已实现**：分页列举、批量删除、目录复制和自嵌套保护。
3. ✅ **上传冲突策略已实现**：包括目录冲突、连续重名探测和 `skip`。
4. ✅ **大文件上传与复制已实现**：multipart upload/copy 均在失败时清理未完成会话。
5. ✅ **S3 404 兼容处理已实现**：同时识别 `NotFound`、`NoSuchKey` 和 HTTP 404，保留权限/服务端错误。
6. ✅ **分页游标重复/缺失保护已实现**。
7. ✅ **CopySource 按路径段编码**，特殊对象名可复制。
8. ✅ **未把 ETag 伪装成 MD5 秒传指纹**；跨盘迁移继续使用可校验、可重放的 spool 上传。

仍属设计范围的能力：S3 不提供统一回收站、服务商托管分享和云端搜索接口。当前仅暴露安全边界明确的临时预签名访问链接。
