# Mnemo v0.2.3

这是一次以 **登录可靠性、跨账号迁移、秒传正确性和发布质量** 为重点的稳定性版本。

本次没有通过伪造浏览器指纹、绕过验证码或规避服务端风控来“强行登录”。对于网盘服务端要求的人机验证、短信验证或频率限制，Mnemo 会在应用内展示对应流程，并保留清晰、可恢复的错误提示。

## 登录与账号

- **PikPak**
  - 重构账号密码登录与内嵌验证码流程；验证码页面继续在登录界面内完成，不再将用户带回外部浏览器登录流程。
  - 登录验证码请求、X-Captcha-Token 提交和一次性重试逻辑与 rclone 参考实现对齐；只有明确的验证码失效响应才会刷新并重试，避免无意义的重复请求。
  - 风控、验证码和冷却时间仍由 PikPak 服务端决定；客户端不会把风控拒绝伪装成“密码错误”，也不会尝试绕过平台安全机制。
- **移动云盘（139）**
  - 完善账号密码登录后的短信安全验证流程，支持获取并提交短信验证码。
  - 修正“服务器未返回登录会话”等不透明失败路径，保留可诊断的登录状态。
- **天翼云盘（189）**
  - 支持账号密码、短信验证码登录以及服务端要求时的图形验证码重试。
  - 验证码过期、错误和短信安全验证会在登录页中明确提示，避免无验证码提示的直接失败。

## 跨账号/跨网盘迁移与秒传

- 现在可以把文件迁移到**同一网盘的另一账号**，不再只面向不同网盘。
- 源账号与目标账号始终使用各自独立的认证上下文和文件缓存；秒传时由源账号读取指纹、目标账号发起创建请求，不会错误复用源账号凭据。
- 迁移策略明确为：**共同内容指纹秒传 → 直传流 → 临时文件回退**。
  - 秒传明确未命中时，且目标支持常规上传，才会继续迁移。
  - 目标状态不明确时停止任务，而不是盲目再次上传，避免重复文件或半成品。
  - move 任务只有在目标完成状态已可靠持久化后才删除源文件。
- PikPak 增加原生 GCID 跨盘/跨账号秒传：仅接受有效的 40 位 GCID，并且只有服务端明确返回完成状态才算命中。
- 移动云盘使用已校验的 SHA-256，天翼云盘使用已校验的 MD5；缺少可靠指纹时不会伪造哈希参与秒传。
- WebDAV 支持迁移链路直接流式 PUT，减少不必要的本地落盘；通用 WebDAV ETag 与 S3 ETag 不再被错误当作 MD5 秒传指纹。
- 一刻相册按产品策略继续**不参与跨盘秒传**，文档与能力声明已明确标注。

> 不同账号之间能否由服务端复用同一指纹，最终由对应网盘的账号策略决定。若服务端拒绝跨账号复用，Mnemo 会在目标支持普通上传时安全回退；这不是客户端可或应当绕过的限制。

## 传输、预览与可维护性

- 拆分原本过大的应用绑定层、网盘驱动、上传/下载、迁移和预览实现，减少重复逻辑并让认证、读写、分享与迁移职责更清晰。
- 补充多项 provider、迁移、流式上传、缓存隔离与异常处理的回归测试。
- 改善文件列表、目录缓存、传输任务轮询、预览文本编辑和播放控制相关的前端状态管理。
- 修正多个网盘上传、分享、列表分页、冲突处理、容量与错误处理边界，减少无效请求和不一致状态。

## 安装包与发布

- Windows 安装后的应用名、开始菜单项、桌面快捷方式和“已安装的应用/卸载列表”统一显示为 **Mnemo**，不再附带版本号。
- 版本号仍保留在文件版本信息、更新比较和“已安装的应用”的版本字段中，以保证升级识别正常。
- Release 工作流现在会校验这一名称约束；若安装器再次把版本号拼进应用显示名，远端质量门会直接失败。
- 远端构建继续提供：
  - Windows x64 / arm64 安装包；
  - Linux x64 / arm64 的 .deb、.rpm、Arch 包、AppImage 与 .tar.gz；
  - macOS Apple Silicon 的 .dmg 与 .tar.gz；
  - 每个正式 Release 的 SHA-256 校验文件。

## 已知限制

- 各网盘的验证码、短信、人机校验和风控由服务端决定；网络、地区、账号状态或访问频率仍可能导致登录被暂时拒绝。
- 秒传是“服务端可复用内容”的优化，不是保证。缺少共同指纹或服务端禁止跨账号复用时，会按目标能力安全回退。
- 一刻相册不支持跨盘秒传；S3 与通用 WebDAV 不会把 ETag 误当作内容哈希。
