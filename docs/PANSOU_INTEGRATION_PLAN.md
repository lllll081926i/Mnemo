# PanSou 内置资源搜索接入计划

> 状态：**规划完成，暂缓实施**  
> 规划日期：2026-08-20  
> 适用版本基线：Mnemo v0.2.1  
> 评估对象：`D:/Code/Mnemo/Example/pansou`

本文只记录产品、架构、交互、风控和测试计划。本轮不接入 PanSou，不修改示例项目，不新增依赖，也不改变现有页面的视觉样式。

## 1. 目标结论

PanSou 作为 Mnemo 的独立“资源搜索”功能接入，拥有自己的页面，不作为第 14 个网盘 Provider，也不要求用户另外启动 Docker、命令行服务或本地 HTTP 服务。

推荐目标形态是：

```text
Mnemo 进程启动
    ↓
读取「启用资源搜索」设置
    ↓
在 Mnemo 进程内初始化 PanSou 搜索核心
    ↓
只加载本地注册表和缓存，不主动访问外部站点
    ↓
用户打开“资源搜索”页面并点击搜索
    ↓
按请求调用已启用的搜索源
    ↓
结果页提供复制、打开、导入/转存等操作
```

第一版必须满足以下产品约束：

1. 用户不需要手动启动任何服务；应用启动时由 Mnemo 自己管理该能力。
2. PanSou 不监听本机 TCP 端口，前端通过 Wails 绑定调用后端能力。
3. 设置中可以完整关闭该能力；关闭后不初始化搜索插件、不启动搜索工作线程、不发起外部请求。
4. 搜索是明确的用户操作，不做输入联想搜索、定时刷新或后台批量校验。
5. 页面独立存在，沿用 Mnemo 当前的轻量、平面、内容优先设计语言，不重做现有页面样式。
6. 搜索结果只在确认支持的情况下显示“导入/转存”，不能因为网盘类型名称相同就误报支持。

## 2. 当前基础与接入边界

### 2.1 PanSou 的现状

只读审查 `Example/pansou` 后确认：

- 项目是独立 Go HTTP 服务，入口负责配置、插件注册、缓存和 Gin 路由。
- 提供 `GET/POST /api/search`、`POST /api/check/links`、`GET /api/health` 等接口。
- 搜索请求支持关键词、频道、插件、网盘类型、结果类型、过滤条件和并发数。
- 搜索结果包含 URL、提取码、备注、时间、来源和按网盘类型分组的数据。
- 仓库包含约 91 个插件目录、约 134 个 Go 文件，插件会访问多个外部站点或频道。
- PanSou 当前 `go.mod` 声明 Go 1.24.1/toolchain 1.24.9，并依赖 Sonic；在本机 Go 1.26.6 下执行其测试时出现 `GoMapIterator` 兼容性错误。
- PanSou 使用 MIT License。若后续复制或改造代码，必须保留版权和许可文本，并逐项核对第三方站点和插件的使用条款。

因此不能把整个 HTTP 服务原封不动塞进 Mnemo，也不能把每一个 PanSou 插件都当成网盘驱动。接入前必须先抽离可调用的搜索核心，并验证 Go 版本、依赖和插件初始化行为。

### 2.2 Mnemo 的现状

Mnemo 当前具备适合承载该功能的基础：

- Wails 的 `App.Startup` 和 `App.Shutdown` 统一管理长生命周期资源。
- `store.Settings` 统一持久化设置，`App.SaveSettings` 负责运行时应用设置。
- `App` 已有上下文、关闭顺序、日志和事件机制。
- 顶层页面由 `frontend/src/App.vue` 的页面组件表和页签表控制。
- `ShareImportDriver` 已支持“解析分享链接、展示文件、转存到已登录网盘”的流程。
- `OpenBrowser` 已对外部链接做协议限制，可复用到搜索结果的打开操作。

计划只新增资源搜索能力，不改动现有 Provider 契约，不让 PanSou 参与网盘登录、目录列表、上传、同步或容量统计。

## 3. 产品定义

### 3.1 独立页面

新增一级页面名称建议为：**资源搜索**。

页面 key 建议使用 `resource-search`，不要使用 `pan`，避免与现有网盘页和网盘搜索概念混淆。页面组件建议为：

```text
frontend/src/views/ResourceSearchView.vue
```

顶栏页签建议顺序：

```text
网盘  ·  传输  ·  同步  ·  分享  ·  资源搜索
```

设置仍通过右上角设置按钮进入，不把设置重复放入顶栏页签。快捷键可以在后续增加 `Alt+5` 或命令面板入口，但必须重新安排现有快捷键，不能覆盖现有操作。

### 3.2 页面关闭时的行为

建议设置字段为 `pansouEnabled`，默认值建议为 `true`，但必须采用懒加载策略：

- 应用启动只初始化本地服务对象、缓存目录和插件注册信息。
- 不因启动而搜索、不刷新频道、不校验链接、不启动后台抓取任务。
- 如果兼容性验证发现某些插件初始化阶段必然联网，则这些插件必须改成显式启用；在完成改造前，默认值应临时改为 `false`。

用户关闭开关后：

- 立即取消进行中的搜索任务；
- 等待 PanSou 工作线程退出；
- 关闭缓存写入句柄；
- 页面从顶栏隐藏；
- 若当前正处于资源搜索页，自动回到网盘页；
- 不删除用户已经收藏的普通链接，但默认不保存提取码。

用户重新打开开关后，服务可以在运行时启动，不要求重启应用。若启动失败，设置页显示失败原因和“重试”按钮，页面不显示半可用状态。

### 3.3 第一版功能范围

第一版只做以下能力：

- 关键词搜索；
- 网盘类型筛选；
- 结果来源和更新时间展示；
- 结果去重和按网盘类型分组；
- 复制链接；
- 复制提取码；
- 使用系统浏览器打开链接；
- 将兼容的链接交给现有分享导入/转存流程；
- 手动刷新单次搜索；
- 清晰区分成功、部分来源失败、无结果、服务未启用和服务异常。

第一版暂不做：

- PanSou 账号体系、JWT 登录界面；
- 用户自定义任意代理并透传给插件；
- 自动批量检查所有链接；
- 自动下载搜索结果；
- 把搜索结果当作云盘账号或目录挂载；
- 将 91 个插件全部开放为用户可调参数；
- 搜索结果云端同步；
- 输入框实时联想和自动刷新。

## 4. 技术架构计划

### 4.1 首选：同进程内置服务，不开放本地端口

目标结构：

```text
internal/pansou/
├── engine/       # PanSou 核心搜索编排、插件调度和结果合并
├── source/       # 搜索源适配与启用清单
├── cache/        # 独立缓存读写与 TTL
├── lifecycle/    # 启动、停止、状态和取消
├── mapper/       # PanSou 结果到 Mnemo 统一模型的转换
└── model/        # 请求、结果、状态、诊断模型
```

Wails 绑定层只暴露 Mnemo 自己的稳定接口，不让前端直接依赖 Gin、PanSou 的内部 JSON 或插件类型：

```text
App.Startup
  → pansou.Manager.Start(ctx, settings)

App.SearchResourceShares(request)
  → pansou.Manager.Search(ctx, request)

App.CancelResourceSearch(requestID)
  → pansou.Manager.Cancel(requestID)

App.GetResourceSearchStatus()
  → pansou.Manager.Status()
```

这样做的好处：

- 不占用本机端口，不产生端口冲突；
- 不需要 CORS、JWT、localhost HTTP 鉴权；
- 前端不能绕过 Mnemo 的取消、超时和日志脱敏策略；
- 应用退出时可以可靠等待 goroutine 和缓存写入结束；
- 后续替换搜索引擎时，页面和 Wails 接口基本不变。

### 4.2 PanSou 核心抽离要求

在真正实施前必须完成一次兼容性 Spike，确认以下事项：

1. 将搜索核心从 Gin Handler 中抽离成可传入 `context.Context` 的 Go 方法。
2. 清理或替换 Sonic 与当前 Mnemo Go 工具链不兼容的部分，优先使用标准库 JSON 或已验证兼容版本。
3. 将全局配置改为实例配置，不能让 PanSou 的全局变量污染 Mnemo 的其他功能。
4. 将插件初始化与外部请求分离，初始化阶段不得访问网络。
5. 将 PanSou 自己的日志桥接到 Mnemo 统一日志格式，禁止把完整 URL、提取码、Authorization 写入日志。
6. 将缓存目录隔离到 Mnemo 数据目录下的 `pansou-cache`，不能复用网盘目录缓存文件。
7. 为搜索任务增加 Mnemo 侧的取消、超时、并发和请求预算。
8. 明确首批启用的“网盘分享源”清单，暂不默认启用与网盘分享无关或请求量特别大的插件。

如果上述抽离无法在不引入大量全局状态的前提下完成，不能直接退回“让用户自己启动服务”的方案。应先暂停实现并重新评估一个由 Mnemo 自动管理的内置伴随进程；该方案只有在同进程方案被证明不可行时才考虑。

### 4.3 服务生命周期

#### 启动

启动顺序建议放在持久化、日志和基础传输资源初始化之后：

```text
打开 Store
  → 读取 Settings
  → 配置日志
  → 初始化基础服务
  → 若 pansouEnabled：创建 Manager
  → 加载缓存和本地插件注册表
  → 启动有限的工作池（不联网）
  → 发布 pansou:status = ready
```

启动失败不能导致 Mnemo 主程序退出。应记录结构化错误，发布 `degraded` 状态，并允许用户在设置中重试。

#### 运行

- 每次搜索都有唯一 `requestID`；重复点击同一请求应被去重或取消前一请求。
- 搜索使用独立 context，默认超时建议 30–60 秒。
- 用户离开页面不自动取消已经明确提交的搜索，但页面提供取消按钮；关闭功能或退出应用必须取消。
- 结果分批返回时，通过 Wails 事件推送进度，但不得在每个插件请求完成时刷新整个页面。

#### 关闭

`App.Shutdown` 中按以下顺序处理：

```text
停止接受新搜索
  → 取消现有搜索 context
  → 等待工作池退出（设置上限）
  → 刷新缓存批量写入
  → 关闭缓存文件
  → 发布 stopped
```

若某个插件卡住，必须由 context 超时保证应用仍能退出，不能让 PanSou 阻塞 Wails 关闭流程。

## 5. 设置设计

### 5.1 设置字段

第一版建议只持久化必要字段，避免把危险的并发参数暴露给普通用户：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---:|---|
| `pansouEnabled` | `bool` | `true` | 是否启用内置资源搜索 |
| `pansouCacheEnabled` | `bool` | `true` | 是否使用本地搜索缓存 |
| `pansouCacheTTLMinutes` | `int` | `30` | 缓存有效期，后端限制范围 |
| `pansouMaxResults` | `int` | `100` | 单次最多返回结果数，后端强制上限 |

并发数、插件白名单、请求预算和超时时间先由后端安全默认值控制。后续确认稳定后，再考虑在高级设置中开放有限选项。

### 5.2 设置页布局

在现有设置左侧导航新增一项：

```text
资源搜索  [search 图标]
```

右侧设置组保持当前 `sg-row` 平面行式布局，不新增厚重卡片：

```text
资源搜索
├─ 启用内置资源搜索                 [开关]
│  内置服务随应用启动，不需要单独运行服务端
├─ 搜索缓存                         [开关]
├─ 缓存有效期                       [UiSelect]
├─ 当前状态                         [运行中 / 已关闭 / 异常]
├─ 已启用来源                       [数量]  [查看详情]
└─ 缓存操作                         [清除缓存]
```

开关旁的说明保持一行以内。服务状态要显示实际状态，不用“已保存”代替“已启动”。关闭时，依赖项使用弱化色并不可操作。

### 5.3 设置保存语义

- 开关变化即时保存并立即启动或停止服务；
- 关闭时如有搜索任务，先弹出一次确认，确认后取消；
- 启动失败时保留用户的开启意图，但将运行状态标为异常，并提供重试；
- `defaultTab` 若指向已关闭的资源搜索页，启动时自动回退到网盘页；
- 老版本设置文件没有新字段时采用默认值，不破坏原有设置。

## 6. 独立页面设计规范

### 6.1 视觉方向

页面严格遵循 `docs/DESIGN.md` 和现有 `design-tokens.css`：

- 轻盈、流动、内容优先；
- 不引入新的品牌色、阴影体系或圆角体系；
- 不使用 Emoji；图标统一使用 `UiIcon.vue`；
- 选中态使用浅色块和主色文字，不使用底部线条指示器；
- 控件使用现有 `.input`、`.btn`、`UiSelect`、`.badge`、`.workspace-empty-state`；
- 新页面样式优先使用 scoped CSS，不修改已有页面的视觉规则；
- 暗色和浅色主题都只引用语义变量；
- 尊重 `prefers-reduced-motion`。

### 6.2 页面信息架构

建议采用“顶部搜索工具栏 + 左侧筛选 + 右侧结果列表”的独立工作区：

```text
┌─────────────────────────────────────────────────────────────┐
│ 资源搜索                         服务状态  [关键词输入] [搜索] │
├───────────────┬─────────────────────────────────────────────┤

│ 网盘类型       │ 夸克网盘                         12 条        │
│ □ 全部         │ ┌─────────────────────────────────────────┐ │
│ □ 123          │ │ 标题 / 备注                         ... │ │
│ □ PikPak       │ │ 来源 · 时间   提取码 [复制] [打开] [转存] │ │
│ □ 阿里云盘     │ └─────────────────────────────────────────┘ │
│                 │                                             │
│ 结果过滤       │ 123 网盘                          8 条         │
│ 包含 / 排除     │ ...                                         │
│                 │                                             │
│ 搜索历史       │ 空状态 / 加载状态 / 部分来源失败状态           │
└───────────────┴─────────────────────────────────────────────┘
```

首版不把页面做成多层弹窗。详情、转存和密码输入使用现有 Modal，避免产生新的弹层交互规则。

### 6.3 顶部工具栏

- 页面标题“资源搜索”与一个简短服务状态徽标；
- 主搜索框为宽输入框，支持 Enter 提交、Esc 清空；
- 搜索按钮使用现有 `.primary`，执行中变为取消按钮；
- 不在输入过程中发请求；
- 状态徽标只显示“就绪 / 搜索中 / 已关闭 / 异常”，详细错误放在结果区或设置页。

### 6.4 筛选区

筛选区使用平面行，不堆叠大量卡片：

- 网盘类型使用 `UiSelect` 或可键盘操作的多选列表；
- 默认选择“全部已支持类型”，但不自动触发搜索；
- 包含/排除关键词属于高级筛选，默认折叠；
- 搜索范围只允许选择已启用的来源，不能让用户输入任意远程 URL；
- 筛选改变后显示“待重新搜索”状态，避免用户误以为列表已经更新。

### 6.5 结果列表

结果按网盘类型分组，每组使用 provider 图标、名称和数量；组内采用现有文件列表的轻量行风格：

- 第一行：资源标题或备注，超长截断并支持悬停查看；
- 第二行：来源、更新时间、链接域名；
- 提取码使用小型 chip，默认不在日志和持久化中保存；
- 行操作只保留当前上下文需要的按钮，次要操作进入菜单；
- “转存”按钮只有在存在对应账号且 Provider 实现 `ImportShare` 时显示；
- 复制成功使用现有 Toast，不弹阻塞式提示；
- 结果列表必须支持分页或虚拟列表，不能一次渲染无限结果。

### 6.6 状态与错误

页面至少区分以下状态：

| 状态 | 展示 | 可执行操作 |
|---|---|---|
| 未启用 | 居中空状态，说明需在设置启用 | 打开设置 |
| 尚未搜索 | 简洁空状态 | 聚焦搜索框 |
| 搜索中 | 进度/来源计数，提供取消 | 取消搜索 |
| 无结果 | 明确“没有匹配资源” | 修改关键词或筛选 |
| 有结果 | 分组列表 | 复制、打开、导入 |
| 部分失败 | 结果照常显示，顶部提示失败来源数 | 查看诊断、重试失败来源 |
| 服务异常 | 不显示假空列表 | 重试、打开设置 |
| 超时/限流 | 显示可读错误和冷却提示 | 等待后手动重试 |

### 6.7 键盘与无障碍

新页面必须从第一版开始具备：

- 搜索框、筛选项、结果行按钮均可 Tab 聚焦；
- Enter 提交搜索，Esc 取消或清空；
- 结果分组使用可读标题，按钮有明确 `aria-label`；
- 加载状态使用 `aria-live="polite"`，不连续播报每一条结果；
- 复制、打开、转存完成后提供可读反馈；
- 详情弹窗沿用现有 Modal 的焦点恢复和 Esc 关闭约定；
- 颜色不是唯一状态表达方式，失败和限流同时显示文字；
- 窄窗口下筛选区可收起，结果操作不被裁切。

## 7. 结果与现有网盘功能的衔接

PanSou 结果不直接变成 Mnemo 文件对象，而是先转换为统一的 `ResourceSearchResult`：

```text
ResourceSearchResult
├── id
├── title
├── providerType
├── url
├── password
├── note
├── source
├── publishedAt
└── actions
    ├── copy
    ├── open
    └── importShare
```

动作判定规则：

1. URL 只允许合法的 HTTPS 链接；磁力和电驴链接进入单独的“复制/离线下载”分支。
2. 先按 URL 解析出 Provider，再检查 Mnemo 是否有对应的登录账号。
3. 再检查目标 Provider 的 `Capabilities.ImportShare` 和 `ShareImportDriver`。
4. 三项都满足时显示“转存”；否则只显示复制和打开。
5. 转存过程复用现有 `ImportShare` / `SaveImportedShare`，不在 PanSou 层重新实现各网盘 API。
6. 转存失败要保留原始搜索结果，不能让失败结果从页面消失。

首批映射需要真实公开测试链接逐项验证，不能只依据名称猜测：

| PanSou 类型 | Mnemo 目标 | 计划动作 |
|---|---|---|
| `aliyun` | `aliopen` | 复制、打开；兼容且已登录时转存 |
| `123` | `pan123` | 复制、打开；已登录时转存 |
| `pikpak` | `pikpak` | 复制、打开；已登录时转存 |
| `guangya` | `guangya` | 复制、打开，后续验证导入 |
| `tianyi` | `pan189` | 复制、打开，后续验证导入 |
| `mobile` | `pan139` | 复制、打开，后续验证导入 |
| `baidu`、`quark`、`uc`、`115`、`xunlei` | 当前没有完整对应能力 | 复制、打开 |
| `magnet`、`ed2k` | 传输/离线下载输入 | 复制，用户确认后转交现有流程 |

## 8. 风控、网络和隐私策略

PanSou 内部可能同时调度多个搜索源，不能沿用“点一次就无限并发”的默认行为。第一版必须有统一预算：

- 单次搜索只允许一个活动请求；重复提交同关键词复用或取消旧请求；
- 后端限制搜索源并发数，建议初始上限 4；
- 每个来源有独立超时和失败隔离，单个来源失败不拖死整体结果；
- 默认使用缓存，不允许页面默认传 `forceRefresh`；
- 同一关键词、筛选条件和版本在短 TTL 内命中缓存；
- 429、403、网络错误只做有限重试，尊重 `Retry-After`，不做无限指数重试；
- `/api/check/links` 不作为第一版自动流程；用户只对选中结果手动触发检查；
- 结果 URL、提取码、Token、Cookie 不进入普通日志；日志只记录来源、状态、耗时、结果数和脱敏域名；
- 搜索结果默认只在内存中存在，用户明确收藏时也只保存必要字段；
- 应用代理可以作为统一网络出口，但不得把任意请求级代理能力暴露给页面；
- 搜索页不自动读取或发送网盘账号密码，PanSou 与网盘登录凭据完全隔离。

服务默认不监听端口，因此无需 CORS 和本地 HTTP 鉴权。若后续由于插件兼容性不得不采用伴随进程，必须额外增加 loopback 绑定、随机令牌、端口生命周期和进程归属校验，并重新评审安全边界。

## 9. 日志与诊断设计

PanSou 相关日志必须接入 Mnemo 统一的简洁格式：

```text
INFO  resource-search search completed source=plugin count=42 duration=8.4s
WARN  resource-search source failed source=xxx status=429 retry_after=60s
ERROR resource-search service start failed error=...
```

必须显示的诊断字段：

- 服务状态；
- 请求 ID 的脱敏短标识；
- 搜索关键词是否存在（不记录完整关键词，可记录长度或哈希）；
- 参与来源数、成功数、失败数；
- 结果数、缓存命中与否；
- 总耗时；
- HTTP 状态或错误类别；
- 冷却时间。

禁止显示或写入：

- 完整分享 URL；
- 提取码；
- Authorization、Cookie、JWT；
- 账号密码；
- 外部站点返回的完整响应正文。

设置页应提供“查看来源状态”和“导出诊断信息”，导出的诊断也必须经过脱敏。

## 10. 测试计划

### 10.1 后端单元测试

- 默认设置和旧版设置迁移；
- `pansouEnabled=false` 时不初始化插件、不创建工作线程、不发起请求；
- 开关运行时启停、重复启停和失败重试；
- App Shutdown 能取消搜索并在超时内退出；
- 请求去重、取消、超时、并发上限和请求预算；
- 缓存命中、TTL 过期、清理和损坏文件恢复；
- PanSou 结果到统一模型的映射、去重、分组和 Provider 动作判定；
- URL、提取码和认证头脱敏；
- 429、403、部分来源失败和返回格式错误；
- `go test -race` 覆盖 Manager 生命周期和结果合并。

### 10.2 Mock 集成测试

使用本地 mock HTTP 源，不访问真实网盘、Telegram 或第三方搜索站点：

- 一个来源成功、一个来源超时、一个来源返回 429；
- 多来源结果合并和重复链接去重；
- 中途取消后不再继续发起新请求；
- 缓存命中时请求计数为零；
- Provider 导入流程只调用现有 mock Provider API。

### 10.3 前端测试

不做浏览器视觉审查，重点测试功能状态：

- 页面在服务关闭、启动中、就绪、异常时正确呈现；
- Enter 搜索、Esc 取消、重复点击去重；
- 筛选状态不会误修改已显示结果；
- 复制链接/密码按钮调用正确的能力；
- 不支持转存时不显示误导按钮；
- 转存失败保留结果并展示错误；
- 设置开关能隐藏/显示页面并回退默认页；
- 键盘焦点、aria 标签和 Toast 反馈。

### 10.4 打包与回归

接入后必须重新验证：

- `go test ./...`、`go vet ./...`、`go build ./...`；
- 前端构建和现有前端测试；
- Windows x64/ARM64、macOS ARM64、Linux x64/ARM64 的云端打包；
- 关闭 PanSou 后的二进制启动和现有网盘功能；
- 启用 PanSou 后的首次启动、退出、重复启动和升级迁移；
- 不产生额外监听端口或残留 PanSou 进程。

## 11. 分阶段实施路线

### 阶段 0：兼容性 Spike（暂不进入产品开发）

目标：用最小代码证明 PanSou 搜索核心能在 Mnemo Go 工具链中同进程运行。

- 盘点插件初始化副作用和外部请求；
- 抽离搜索核心接口；
- 处理 Sonic/Go 版本兼容；
- 验证缓存和工作池关闭；
- 只启用一两个 mock 搜索源；
- 确认二进制体积、启动耗时和内存增量。

通过标准：不监听端口、启动不联网、可取消、可关闭、无 goroutine 泄漏。

### 阶段 1：内置服务骨架与设置

- 新增 `pansouEnabled` 等最小设置字段；
- 接入 `App.Startup`/`Shutdown`；
- 实现状态事件和重试；
- 建立独立缓存目录和统一日志桥；
- 写生命周期和配置测试。

### 阶段 2：独立资源搜索页面

- 新增 `ResourceSearchView.vue`；
- 增加顶栏页签和页面可见性逻辑；
- 完成关键词、筛选、分组结果和状态页；
- 完成复制、打开和错误反馈；
- 不改现有页面样式文件中的既有规则。

### 阶段 3：分享导入衔接

- 接入 Provider 类型映射；
- 只为已验证的 `ImportShare` 能力显示转存；
- 复用现有分享导入 Modal 和转存流程；
- 补 mock Provider 集成测试。

### 阶段 4：风险控制与质量收尾

- 加入请求预算、缓存、429 冷却和取消；
- 完成敏感字段脱敏；
- 完成前端交互测试和 race 测试；
- 完成五种目标平台云端打包回归；
- 更新 README、架构文档、Provider 状态和发布说明。

### 阶段 5：可选增强

只有第一版稳定后才考虑：

- 搜索历史和收藏；
- 来源诊断详情；
- 用户选择搜索源；
- 单条链接有效性检查；
- 更多网盘导入适配；
- 在确认同进程不可行时，再评估自动管理伴随进程。

## 12. 粗略工作量与风险等级

| 工作项 | 复杂度 | 备注 |
|---|---:|---|
| PanSou 核心同进程抽离 | 高 | 最大不确定性，取决于全局状态和插件副作用 |
| 设置与生命周期管理 | 中 | 可复用现有 App/Store 结构 |
| 独立搜索页面 | 中 | 页面独立，沿用现有组件和设计令牌 |
| 结果映射与分享导入 | 中 | 需要逐 Provider 验证公开测试链接 |
| 风控、缓存和取消 | 中高 | 必须优先于扩大插件数量 |
| 跨平台构建和依赖维护 | 中高 | Sonic/Go 版本和二进制体积需要持续关注 |
| 全量启用 91 个插件 | 很高 | 不建议作为第一版目标 |

预计在兼容性 Spike 通过后，MVP 需要约 2–4 周有效开发量；如果 Spike 证明 PanSou 无法干净地抽离，时间和维护成本会显著上升，应重新决策，而不是直接扩大 Mnemo 主程序复杂度。

## 13. 暂缓期间的决策清单

后续开始实施前，需要逐项确认：

1. 首批启用哪些搜索源，是否只保留网盘分享相关插件；
2. `pansouEnabled` 是否保持默认开启；前提是启动阶段严格不联网；
3. 是否允许使用 Mnemo 全局代理；
4. 首批哪些 Provider 允许显示转存按钮；
5. 是否保存搜索历史；默认建议不保存提取码；
6. PanSou MIT 代码和各插件第三方条款如何在发布包中保留说明；
7. 若同进程抽离失败，是否接受由 Mnemo 自动管理的 loopback 伴随进程。

在这些决策完成前，不修改 `App.Startup`、`store.Settings`、`App.vue` 或任何 Provider 代码。

## 14. 完成定义

PanSou 接入只有同时满足以下条件才算完成：

- 用户无需手动启动服务；
- 关闭设置后不会发起任何 PanSou 外部请求；
- 服务启动失败不影响 Mnemo 原有网盘功能；
- 搜索任务可取消、限流、超时并在退出时回收；
- 日志不泄露链接、密码或令牌；
- 页面拥有独立的信息架构，但视觉上与现有 Mnemo 一致；
- 只有真实验证过的 Provider 才显示转存；
- 断网、限流、部分失败、无结果和服务关闭均有不同反馈；
- 全部本地测试与云端多平台打包通过；
- 文档、许可证和发布说明同步更新。
