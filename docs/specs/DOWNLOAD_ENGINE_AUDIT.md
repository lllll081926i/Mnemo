# 下载引擎审计与修复规范

日期：2026-10-04。范围：统一下载器、任务管理器、14 个网盘的下载源与策略、传输设置。

状态：源码审计、已确认缺陷修复与自动化核验完成；真实账号公网测速仍待验收，详见 `docs/DOWNLOAD_ENGINE_AUDIT_2026-10-04.md`。

## 目标与边界

- 修复客户端造成的低速、下载头丢失、恢复错误和长时间无响应问题。
- 任务并发与单文件连接数独立：默认同时 3 个任务、每文件最多 8 个请求；用户可设置每文件 1–16 个连接。
- 网盘显式连接上限优先；预览代理模式不能隐含限制本地下载连接数。不擅自解除已有单连接策略。
- 下载暂停后恢复必须重新获取账号下载源，包括请求头、鉴权器、分片策略和签名 URL。
- 保留专用 UA；只在网络读取期间应用空闲超时，用户限速及磁盘写入不算网络空闲。
- 永久 HTTP 错误不盲目重试；临时 HTTP 错误有界重试，遵守 Retry-After 并协调同一下载的请求。
- 保证 Range 校验、内容校验、签名链接变化后的安全续传、全局限速和取消语义。
- 本地性能测试只能证明客户端行为，不能代替真实账号公网测速；服务商套餐、CDN、风控限制必须明确区分。

## 核验

新增回归测试覆盖请求头、独立连接设置、策略上限、恢复重新解析、网络空闲超时、状态重试与等待取消。使用本地受控服务比较 1 与 8 连接的传输时间并逐字节核验文件。运行相关测试、race、全量 Go 测试、vet、前端测试及编译检查，不生成验证版或安装包。
