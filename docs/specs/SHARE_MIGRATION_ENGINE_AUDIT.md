# 分享与迁移引擎审计规范

## 范围

- 覆盖全部 14 个注册网盘的创建分享、撤销、转存能力与入口，以及统一跨盘迁移流程。
- 以当前代码、模拟协议回归为依据；不创建真实公开分享，不删除真实用户文件，不生成验证安装包。

## 安全约束

- 移动迁移清理来源前，必须重新确认目标存在、类型和大小相符；可比较的内容哈希也必须相符。恢复旧任务同样执行检查。
- 目标 ID 缺失、远端查询失败或检查点保存失败时，保留来源，不把请求成功当成文件可靠落盘。
- 驱动详情中的占位大小或内存池不能作为新鲜元数据；目标按所属目录的远端列表核对。
- 目录创建和完成检查点保存失败必须传播；退出取消全部迁移并等待收尾，不再接受新任务。
- 分享已有链接的复用只允许明确的已存在错误，不掩盖网络、权限或限流错误。
- 分享列表消费完整分页，异常分页不能返回不完整的成功结果；转存目录路由与用户选择一致。
- 能力开关与完整驱动实现保持一致，未实现的接口不得为满足数量而开启。

## 核验与交付

- 先补缺陷回归，运行相关包与竞态测试，再运行全量测试、静态检查、编译检查。
- 审计报告逐盘列出实现、限制和剩余风险，区分本地协议验证与真实账号验收。
