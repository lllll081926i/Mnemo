# 上传引擎审计规范

## 范围

- 检查全部 14 个驱动、上传队列、全局限速、上传会话保存，以及目录同步和跨盘迁移调用路径。
- 区分任务并发、单文件分片并发、接口节流、会员限制；不得把客户端常量称为官方上限。
- 迅雷当前未实现上传，必须明确标注，不因审计开启空实现。

## 本轮修复原则

- 先用本地测试复现错误指纹、未确认就完成、短读被忽略、取消不及时、恢复进度错误和退出时序问题，再修复。
- 同一个远端会话才能恢复其分片；服务端确认成功前不清除检查点。
- 取消后等待上传 worker 和分片收尾；不得让后台分片继续读取已经关闭的文件。
- 不对创建、提交或自动改名请求增加无条件重试，避免重复文件或不确定提交被重放。
- 不擅自提高全部网盘的并发，不承诺突破服务端限速。

## 核验与交付

- 执行相关回归测试、竞态测试、全量 Go 测试和编译检查；不生成安装包或验证版。
- 审计报告列出每个网盘的实际上传路径、当前分片及并发、恢复与限制、已修复和遗留风险。
- 本轮没有真实账号写入和公网测速；协议测试通过不等于全部服务端上传已验收。
