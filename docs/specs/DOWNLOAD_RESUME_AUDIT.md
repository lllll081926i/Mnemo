# 下载断点续传审查

## 目标

审查全部 14 个网盘共用的下载路径。优先修复光鸭完整单流降级后重启丢失进度的问题，不降低资源身份、响应范围和长度校验。

## 实施

- 为完整单流和小文件保存顺序字节检查点；恢复时使用条件 Range 请求，校验通过后才追加数据。
- 光鸭探测修改时间不稳定时，以实际完整响应的身份保存单流检查点；恢复仍校验此前响应的身份，不混合不同资源。
- 分段下载定期保存未完成片的有效前缀，不再只在分片完成或正常停止时保存。
- 任务重启时从本地有效检查点恢复显示进度，不用稀疏临时文件长度推算完成量。
- 检查所有驱动的请求头、鉴权、并发策略、稳定资源 ID 和签名 URL 更新路径。

## 核验

- 单流暂停与重启、签名 URL 更新、小文件、光鸭修改时间漂移及单流降级。
- 条件 Range 被忽略、资源身份或长度变化、错误范围、缺失或截断临时文件。
- 未完成分片在进程未正常收尾时的检查点恢复。
- 下载管理器重建后的进度与实际可续传字节一致。
- Go 专项测试、全量测试、竞态检查、静态检查和编译检查；不生成验证版。

## 边界

服务端不支持 Range、无法确认资源身份、签名刷新后文件身份变化时，客户端不能安全保留旧字节。保留明确日志并从头下载，不伪造续传成功。
