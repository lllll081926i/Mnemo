# 密码与短信验证码登录切换

## 界面与能力约束

- 同时提供密码和短信验证码登录的网盘，在右侧登录区顶部显示全宽双选项切换，每项占一半宽度。
- 选项名称统一为“密码登录”和“短信验证码登录”；只提供一种方式的网盘不显示切换，不把 Token、Cookie 或 OAuth 当成第三项。
- 由驱动的 `login_mode` 字段声明支持的方式，前端统一渲染，不按网盘名称制造未实现的登录入口。
- 切换时保留手机号，清除另一方式的密码、验证码、图片和临时验证会话；发送中的请求不能污染切换后的表单。
- 请求期间禁止切换，短信重发限制与账号、设备及原验证会话保持一致。

## 迅雷短信登录

- 必须先核实迅雷官方短信登录端点、验证参数与授权交换方式；不能将登录后的短信安全校验冒充免密码短信登录。
- 验证码及发送 Token 只存在于限时、账号和设备绑定的临时会话，不保存验证码，不跳过官方风控，不自动创建账号。
- 模拟协议测试与真实账号验收分开记录，不生成验证版或安装包。

## 核验

- 当前双方式驱动：迅雷、移动云盘、天翼云盘。光鸭仅提供短信登录，PikPak 等当前只提供密码或授权的驱动保持原入口。
- 迅雷端点参考已核查官方 2026-09-16 网页 SDK，发送 / 校验 / 登录、两阶段风控、切换取消、过期和重发限制已有模拟测试；未向真实手机号发送验证码，不宣称真实账号验收通过。

- 覆盖可用方式声明、等宽样式、切换清理、表单必填规则、请求参数、过期与取消、短信重发以及旧回调隔离。
- 执行相关 Go 与前端测试、编译检查，保留无关的现有工作区修改。
- `frontend/login-methods.browser.cjs` 使用本地模拟接口，后台核验浅色与深色主题、1440 与 720 像素窗口下的全宽等分布局、字段切换及凭据清理，不访问真实账号。
