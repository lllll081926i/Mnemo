## 合并前需要处理的问题

### R1：账号状态没有在重新授权和重启后同步（P2，M01）

位置：PR 的 `frontend/src/App.vue:248`、`:294`、`:493`。

过期事件只向内存 `accountHealth` 写入 `auth`。重新登录成功后后端已清空 `auth_state`，但 `account:changed` 只调用 `refresh()`；该函数不更新健康状态，侧栏仍显示“登录失效”。反过来，重启后读取到 `auth_state=reauth_required`，前端也不把它还原到 `accountHealth`，重新授权提示消失，直至再次触发错误或手动检查。

两个新增组件反例均失败：

- 过期 → 同一账号重新授权 → `account:changed`：预期不再是 `auth`，实际仍为 `auth`。
- 新窗口加载持久化失效账号：预期为 `auth`，实际为 `undefined`。

建议：在账号列表同步时统一处理持久化认证状态；确认同一主体重新授权成功后清除旧认证错误。不要因普通列表刷新直接清掉网络、额度等独立健康信息。补齐重启及重新授权的组件回归。

### R2：新建离线任务仍会明文保存部分签名（P2，B-19）

位置：PR 的 `internal/app/offline_url.go:27`。

敏感参数采用名称黑名单，匹配 `sign` 却未匹配 `sig`。例如输入 `https://example.test/file?sig=review-secret&sp=r&se=2099-01-01`，输出仍完整包含 `sig=review-secret`，随后由创建及刷新路径保存到 `offline.json`。这不只是文档已承认的“旧记录尚未迁移”，新记录也有脱敏漏项。

新增 `TestPR1ReviewOfflineSignatureIsNotPersisted` 已复现。建议显示链接默认移除查询值，或只保留明确允许的非敏感字段；若业务必须保存原链接，走现有凭据加密存储。旧历史仍需单独迁移。

### R3：清理已完成上传仍会使内存与磁盘不一致（P2，B-02）

位置：PR 的 `internal/transfer/upload.go:789`、`:808`，`internal/store/tasks.go:331`。

内存遍历会跳过仍在 `q.runs` 中的任务，磁盘清理却继续按全部 `IsCompleted` 批量删除。任务已写入完成状态、worker 尚未退出时点击清理，内存留下任务，磁盘记录被删除。新增反例得到“内存 1 项、持久化 0 项”。这属于审计中明确要求但本 PR 尚未补齐的旧问题，不能描述为本 PR 新引入。

PR 已正确保留失败和暂停任务；本问题不证明失败任务仍被误删。建议按本次实际清理的 UploadID 删除磁盘记录，并协调 worker 状态与持久化顺序，报告持久化失败，而不是再次按全局状态筛选。

### R4：最新提交的 CI 仍失败（P1，交付阻断）

位置：PR 原有 `frontend/src/components/interaction.test.js:1519`，对应账号过期测试。

该测试仍要求“已从本机移除”和“云端文件不会被删除”；实际逻辑已改为保留账号及任务。两条云端质量检查均失败，本地原始 PR 前端测试同样为 **240 通过、1 失败**。

这是旧断言与新语义冲突，应更新为保留账号、选择、缓存与任务的断言，并同时补 R1 的行为覆盖；只替换提示文本不足以证明账号生命周期修复完整。

云端证据：[PR 检查](https://github.com/lllll081926i/Mnemo/actions/runs/38010974012)、[分支检查](https://github.com/lllll081926i/Mnemo/actions/runs/38010971550)。
