# 全审计整改：阶段六

## 范围与修复

推进 M18、M33 的通用控件和关键键盘路径，不改产品视觉体系，不以自动化结果替代原生辅助技术验收。

- `UiSelect` 原实例计数器位于 setup 内，多个实例生成相同 ID。改用 Vue 实例 ID；`SegTabs` 同样隔离 ID，防止方向键把焦点切到另一组按钮。
- 下拉采用组合框焦点模型。焦点留在触发按钮，活动选项通过 `aria-activedescendant` 关联和滚动；选项不额外占用 Tab 顺序。
- 移除全局下拉方向键监听，不再劫持其他输入框。未选择时从首项开始，跳过原生禁用项；选项更新、控件禁用和焦点离开时清理浮层状态。
- Escape 先关闭下拉。Tab 关闭下拉后继续弹窗焦点循环，不吞掉外层键盘事件。
- 弹窗过滤隐藏、inert、disabled 和负 tabindex 控件；自身获焦时正确循环；关闭底层弹窗不把焦点抢出顶层弹窗。
- 设置输入、开关、分段按钮和选择器补充可访问名称；同步开关名称包含任务名。高对比度模式保留焦点、选中和双栏活动边框。

## 验证

- 新增 8 项通用控件回归，以及设置控件名称回归。前端全量 28 个测试文件、266 项测试通过；生产构建通过，保留既有大分块警告。
- 完整工作区浏览器脚本通过；二级弹窗专项维持贴角规则。
- 新增 `QA_ACCESSIBILITY_ONLY=1` 浏览器验收：设置页无重复 ID，开关和输入有名称；两种窗口、三种主题和三档 CSS 缩放共 18 个组合下，组合框焦点及活动选项关联正确。
- 单独启用 forced-colors 和 reduced-motion，验证可见焦点；同步编辑弹窗的 Escape 先关闭选项，再关闭弹窗，最后恢复原按钮焦点。无 pageerror。

运行方式与既有工作区脚本相同，额外设置：

```powershell
$env:QA_ACCESSIBILITY_ONLY = '1'
node workspace.browser.cjs
```

浏览器使用本机模拟数据，不操作真实网盘。CSS 缩放不是原生 WebView DPI 测试；没有据此宣称屏幕阅读器、所有页面颜色对比或全站 WCAG 达标。真实 Windows 高对比度与辅助技术仍需人工验收。
