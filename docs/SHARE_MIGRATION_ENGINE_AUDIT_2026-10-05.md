# 分享与跨盘迁移引擎审计（2026-10-05）

## 结论

- 覆盖 14 个注册网盘的分享能力声明、创建和撤销路径、3 个分享转存驱动，以及统一跨盘迁移、检查点、恢复、退出和前端提交入口。
- 当前有 10 个创建分享驱动、3 个分享转存驱动、5 个远端撤销驱动。能力注册、驱动实例和门面开关已增加一致性回归；没有发现实现完整但未开启的分享转存驱动。
- 最重要的缺陷是移动迁移原先只核对来源，未重新确认目标。现在目标缺失、大小不符、可比较哈希不符或无目标 ID 都会阻止删源，恢复旧任务也不例外。
- 迁移性能仍有明确限制：14 个驱动均未实现直接流上传接口，秒传未命中时实际是单请求下载到临时文件，再上传；不能把“代码里有流式分支”当成已支持所有网盘的下载上传并行。
- 本轮没有操作真实云端文件，没有创建公开链接，也没有生成 EXE、验证包或安装包。模拟协议与本地测试不能替代真实账号、风控和套餐验收。

## 逐盘分享结果

“撤销”指真正向服务端撤销，不是删除本地历史；“转存”指分享文件转入同服务商账号，不是跨盘迁移。

| 网盘 | 创建范围 | 转存 | 撤销 | 实际限制与本轮发现 |
|---|---|---|---|---|
| PikPak | 多文件/目录 | 有 | 有 | 密码参数目前触发加密分享，正文未传自定义密码，最终访问码以服务端回执为准；有效期格式错误曾静默变为永久，已修复 |
| 阿里云盘 | 多文件/目录，同一空间 | 有 | 有 | Open 创建/撤销仅在明确 404 后回退原生路由；转存备份盘曾错误使用资源盘 ID，链接内密码曾被忽略，均已修复 |
| 123 云盘 | 多文件/目录 | 有 | 无 | 分享列表原先只取首个 100 项页，已改为完整分页，重复 ID/超限报错；转存提交异步请求，尚无任务完成轮询 |
| 移动云盘 | 个人云多项 | 无 | 无 | 家庭云公开分享明确拒绝；永久/1/7 天，访问码由服务端生成；文件夹类型依赖传入 FileRefs |
| 天翼云盘 | 个人云单项 | 无 | 无 | 家庭云公开分享明确拒绝；永久/1/7 天，访问码由服务端生成 |
| 普通蓝奏 | 单文件/目录 | 无 | 无 | 分享码由服务端决定，不支持自定义有效期；文件/目录请求有类型回退，错误细节会被简化 |
| 优享蓝奏 | 未开放 | 无 | 无 | 没有完整创建分享/转存驱动，不虚假开启 |
| 一刻相册 | 未开放 | 无 | 无 | 相册产品的分享功能不等于本项目已有完整驱动 |
| OneDrive | 单文件/目录 | 无 | 有 | Graph 匿名链接、密码、期限受账号和组织策略约束；撤销依赖文件 ID 与权限 ID |
| Dropbox | 单文件/目录 | 无 | 有 | 原先任意创建错误都会尝试复用或改写旧链接，已收敛为明确“链接已存在”；复用时应用本次权限/期限设置，修改缺链接不报成功 |
| 光鸭云盘 | 多文件/目录 | 无 | 有 | 永久/1/7/30 天入口，自定义访问码；检查资源 API 业务响应，撤销走远端批量接口 |
| 迅雷网盘 | 未开放 | 无 | 无 | 本项目暂无完整分享驱动；也未实现本地文件上传，不能作为普通迁移目标 |
| WebDAV | 未开放 | 无 | 无 | 标准协议没有通用的公开分享、访问码和有效期接口 |
| S3 | 单对象预签名 URL | 无 | 无 | 1/7 天，无密码，不能单独撤销，不写分享历史；实际期限还受临时凭据有效期影响 |

3 个分享解析器已共用域名与协议校验：支持项目现有的正式域名和别名，拒绝跨服务商、伪装后缀、带用户信息或非 HTTP(S) 的链接。不向用户输入的任意地址转发登录凭据。

## 逐盘跨盘迁移结果

“来源/目标”表示项目已有下载/上传路径，不表示已经对全部 14×14 组合做真实联机验收。秒传需要来源提供的算法与目标接受的算法一致；Yike 明确不参与跨盘秒传。

| 网盘 | 可作来源 | 可作目标 | 注册哈希：提供 / 接受秒传 | 删源前目标确认的限制 |
|---|---|---|---|---|
| PikPak | 是 | 是 | — / — | 普通上传可返回目标 ID；跨盘不凭本地 GCID 假定秒传能力 |
| 阿里云盘 | 是 | 是 | SHA1 / SHA1 | 上传及秒传返回 ID 已保留 b:/r: 空间前缀，避免资源盘目标误查到备份盘 |
| 123 云盘 | 是 | 是 | MD5 / MD5 | 按明确目标 ID 查远端；不再仅凭非命中秒传响应里的 ID 判成功 |
| 移动云盘 | 是 | 是 | SHA256 / SHA256 | 个人云普通/秒传上传现已记录目标 ID；家庭云上传仍缺最终 ID，移动迁移保留来源 |
| 天翼云盘 | 是 | 是 | MD5 / MD5 | 普通提交可返回带空间 ID；秒传返回命中但无文件 ID 时，移动迁移保留来源 |
| 普通蓝奏 | 是 | 是，受会员大小/扩展名限制 | — / — | 当前上传无明确最终 ID，移动迁移不删源；现在下载之前先执行目标上传限制检查 |
| 优享蓝奏 | 是 | 是 | MD5 / MD5 | 普通和秒传路径有文件 ID，仍依赖远端元数据质量 |
| 一刻相册 | 是 | 是，遵守相册语义 | — / — | 当前上传没有统一目标 ID 回执，移动迁移不删源；没有跨盘秒传接口 |
| OneDrive | 是 | 是 | SHA1、QuickXorHash / — | 上传返回目标 ID；QuickXorHash 不等于 MD5/SHA1 |
| Dropbox | 是 | 是 | Dropbox 内容哈希 / — | 返回目标 ID；其分块组合哈希不能冒充普通 SHA256 |
| 光鸭云盘 | 是 | 是 | MD5 / — | 新上传任务有目标 ID；旧单 PUT 无任务 ID 的路径不能作为删源依据 |
| 迅雷网盘 | 是 | 否 | — / — | 可以迁出，不能把服务端云离线当成本地上传能力 |
| WebDAV | 是 | 是 | — / — | 已补实际 PUT 路径回执，重命名后记录真实路径；清理来源是永久删除 |
| S3 | 是 | 是 | — / — | 已补包含挂载前缀换算的实际对象 ID；不把 multipart ETag 当成 MD5，清理来源是永久删除 |

## 本轮修复

### 迁移安全和恢复

1. 移动清理来源前复查目标存在、类型、文件大小和双方相同算法的可用哈希；无法确认时标记部分完成并保留来源。
2. `CopiedFileIDs` 恢复路径同样复查目标，不把过去的复制记录当成目标永远存在。
3. 初始来源查询绕过 UI 快照，避免以旧文件大小/时间/哈希作为本次迁移基准。新增 FreshFileDriver：123 冷查询绕过驱动内存池；蓝奏、优享蓝奏、天翼及移动家庭云缺少所属目录时拒绝用缓存或占位详情校验。目标检查使用完整远端父目录列表，不信任冷详情中的大小 0。
4. 目录创建、单项完成、最终状态等检查点保存错误不再静默忽略；保存失败中止当前任务。复制检查点保存失败撤回内存中的新增标记，不允许随后以未落盘记录删源。
5. 部分完成错误保留原始取消、超时和检查点错误，目录递归能正确传播停止原因。
6. 退出取消全部迁移后等待已注册任务保存状态、结束上传和清理临时文件，拒绝关闭后的新任务。
7. 进度事件、启动和恢复响应深复制 map/slice，不把后台继续修改的任务对象交给界面序列化。
8. 拒绝空/重复文件选择；目标提供上传限制时，在下载正文之前校验；预检也使用同一可取消的校验门面。
   123 普通上传和跨盘秒传都要求明确 Reuse 命中，不再用“缺少 Key”推断秒传成功。
9. 移动迁移提交入口检查来源有移除能力，不能把普通盘内移动开关当成删除接口。
10. 事后校验优先比较保存的迁移时来源哈希，不依赖已经被移动删除的来源；目标目录不能因大小为零而冒充空文件。

### 分享正确性

1. 123 分享文件完整分页，防止第 101 项以后的文件不可选；异常重复页不返回不完整成功结果。
2. 阿里转存按所选备份/资源空间路由，并消费链接中的提取码。
3. Dropbox 只在明确链接已存在时复用，不掩盖权限或网络错误；复用应用本次期限和访问方式。
4. PikPak 无效或已过期的有效期直接报错，不再悄悄创建永久分享。
5. 分享导入界面不把无回执或数量不足算作全部成功；正常响应只提示“已提交转存”，不声称已经落盘。
6. 注册一致性测试覆盖全部网盘，区分已实现转存、可撤销分享和未实现的直接流上传。

## 尚未解决的限制与建议顺序

### 优先级高

- **分享转存缺完成状态模型**：PikPak restore、123 async、阿里 copy 目前主要确认请求被接收，返回值使用分享中的来源 ID，而不是可靠的目标 ID；阿里逐项失败虽返回部分成功列表和 error，Wails 错误通道不能完整传递双方信息。下一步应增加提交/进行中/部分成功/完成结果类型和任务轮询，而不是盲目重试整批。当前界面已避免把提交显示为完成。
- **部分目标缺最终文件 ID**：蓝奏、一刻、移动家庭云及光鸭旧上传路径仍需完善回执；现在这些移动任务安全降为部分完成，来源不会因无法验证而删除。不要通过同名猜测目标来绕过保护。
- **缺少目录元数据的旧任务**：部分驱动没有独立文件详情接口。旧任务冷恢复时可能需要先刷新来源目录；目标检查点缺少父目录时保留来源，而不是把占位零字节文件当成真实文件。
- **元数据检查不等于事务**：来源变化检查到真正删除之间、目标检查到来源删除之间仍存在竞态。无共同哈希时只能核对大小；来源修改时间精度可能不足。服务商未提供版本条件删除时，不能承诺完全杜绝同大小文件被替换的问题。

### 性能和恢复

- 单个迁移任务逐项执行；非秒传路径每项单 GET 下载完后才上传，没有接入原生 Range 分段下载、直链自动刷新或下载片段断点恢复。退出后的临时文件会清理，下次重试重下这一项。
- 临时文件位于系统临时目录，不是用户下载目录；没有空间预留或可靠的剩余空间预检。蓝奏 multipart 暂存可能额外消耗一份正文空间。
- 不同迁移任务和普通上传队列没有统一目标写入锁，也没有共同的迁移任务并发总闸；共享限速不等于共享并发限制。
- 同名文件默认 rename，但部分目标上传协议仍有策略差异；目录 Mkdir 没有统一 rename 契约，恢复复用旧目标目录也缺完整子树校验。不得自动覆盖来提速。
- 复制成功与检查点落盘、来源删除与完成记录落盘之间不存在跨云事务；极端崩溃时仍可能重复复制或需要人工对账。只有同一个 jobID 禁止重入，两个不同 jobID 的同一来源不互斥。
- 递归执行没有统一的深度/循环硬上限；预检有重复 ID 和 20000 项保护，执行过程还需同级保护。进度的 Total 统计顶层选择，字节分母逐步发现，不是完整预扫描值。

### 分享管理

- 分享操作仍主要使用后台 Context，不统一绑定应用退出；持久化历史存访问码及公开链接，是本地文件权限保护而非账号凭据加密。
- 历史只记录组合分享的首个来源 ID，不能恢复完整选项；没有远端分享列表全量对账和跨进程的分享转存恢复队列。
- PikPak 的“自定义提取码”声明需要真实协议依据进一步收敛：当前请求只设置 REQUIRED，实际码来自服务端。不能仅凭返回 mock 恰好等于输入认定自定义已实现。
- OneDrive、Dropbox 期限/密码支持取决于套餐和租户；S3 七天是签名上限，不保证临时凭据存活七天；非开放 API 网盘仍受协议变化和风控限制。
